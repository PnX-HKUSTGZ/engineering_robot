# target_redeem_box

本文档描述了[target_redeem_box]中目标检测与定位模块的架构设计。该架构旨在实现模块化、可扩展性、可维护性和高效的数据处理。

## 核心设计原则

**模块化 (Modularity)**: 将不同的检测算法和功能单元分离到独立的类中。
**单一职责原则 (Single Responsibility Principle)**: 每个类或模块只负责一部分明确的功能。
**接口隔离 (Interface Segregation)**: 定义清晰的接口，使得模块间的依赖最小化。
**依赖倒置原则 (Dependency Inversion Principle)**: 高层模块不依赖于低层模块的具体实现，两者都依赖于抽象（接口）。
**高效数据处理**: 尤其注意避免大型数据（如点云）的不必要复制。
**可配置性**: 允许通过配置文件灵活地启用、禁用和调整检测器及其参数。
**线程安全**: 在多线程ROS节点环境中安全地处理数据。

## 核心架构

目标检测模块的架构有两个部分组成：

1. detect_manager
    1. 负责加载配置文件，初始化检测器，并根据配置文件动态启用或禁用检测器。
    2. 订阅数据，将数据分发给所有已启用的检测器。
    3. 每个检测器运行在一个单独的线程中，并行处理不同的目标类别。
    4. 负责将检测结果发布到ROS话题。
2. detector
    1. 负责目标检测的具体实现
    2. 并且每一个detector中都包含了一个`rclcpp::node`的指针，使其也拥有了作为一个单独的node的功能，方便发布一些数据调试

这样设计的目的是为了方便后续开发以及实现配置分离，让每一层都只专注于自己的任务。

在配置方面。相较于之前的写法，这个写法使得架构更加清晰，有效防止了单个类中出现大量的不同的detector的参数

在后续开发上面，只需要在detector_manager中添加小小的几行，并且实现一个新的detector即可。

## 算法实现

### ArrowDetector类

首先轮廓检测+约束条件筛选出我们想要的箭头轮廓（后续可以使用深度学习实现这一步）

然后对筛选出的轮廓进行角点提取，我在这里尝试提出一个对于任意多边形提取较为准确角点的方法。

1. 对轮廓进行多边形拟合，从多边形中得到第一组角点 `corner1`
2. 将轮廓放在一张单独的单通道图上，或者通过某种方式将原图盖上`mask`后使用`canny`得到这张图
3. 然后开始搜索，得到每一条边对应的所有点，注意在这里的时候，我们会忽略粗略角点附近的区域，以区分每一条边
4. 使用直线拟合，得到每一条边的直线方程
5. 求交点即可
